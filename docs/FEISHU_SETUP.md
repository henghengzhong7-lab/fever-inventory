## 一、你现在要做的（大约 3 分钟）

### 第 1 步 ⭐ 把主页地址换成线上服务

**位置**：开发者后台 → 你的应用 → 左侧「**网页应用**」

这里有 **桌面端主页** 和 **移动端主页** 两栏，把里面的
`https://henghengzhong7-lab.github.io/fever-inventory/` 换成：

```
https://fever-inventory.app.workbuddy.host/
```

为什么要换：这个新地址**界面和接口同域**，不用处理跨域，国内访问也比 `github.io` 稳得多。
而且只有这个版本才带登录层和共享数据能力——旧的静态版无论怎么配都共享不了数据。

---

### 第 2 步 ⭐ 把同一个地址加进「重定向 URL」

**位置**：开发者后台 → 你的应用 → 左侧「**安全设置**」→「**重定向 URL**」

把**同一个地址**原样加进去（带结尾斜杠）：

```
https://fever-inventory.app.workbuddy.host/
```

飞书官方《飞书客户端内网页应用接入指南》第一步就是「配置重定向地址」，原文：

> 请确保调用端内网页应用授权接口的页面地址已添加在重定向 URL 的列表中。

免登拿授权码的页面如果不在这个列表里，会被直接拒绝。**这一步别跳。**

---

### 第 3 步 ⭐（要用扫码才需要）配「H5 可信域名」

**位置**：开发者后台 → 你的应用 → 左侧「**安全设置**」→「**H5 可信域名**」

如果队员要在**飞书客户端里扫码**，这一栏必须填。填的是**完整 URL**（后台校验要 `https://`
开头，只写主机名会被拒）：

```
https://fever-inventory.app.workbuddy.host
```

为什么要它：免登用的 `tt.requestAccess` 是**免鉴权**接口，所以不配也能进系统；
但扫码用的 `tt.scanCode` 是**需要鉴权**的 JSAPI，没配可信域名，鉴权就过不去 ——
表现为点「开始扫码」没反应。鉴权本身由服务端算签名（`/api/jsapi-config`）、
前端交给 `h5sdk.config` 完成，你只要把域名配上即可。

#### 配好了没有，页面上直接看得见

手机飞书里打开应用 → 「扫码查物」，按钮下面有一行小字，写的是飞书扫码的准备情况：

| 这行字 | 说明 |
| --- | --- |
| `飞书扫码：已就绪` | 配置正确，直接扫 |
| `飞书扫码没就绪：JSAPI 鉴权失败：…H5 可信域名…` | 域名没配或配错了，回去检查第 3 步 |
| `当前不在飞书客户端里` | 是用手机浏览器打开的，走摄像头 / 拍照识别即可 |

把这行字截图发给维护的人，就能直接定位，不用猜。

#### 为什么"电脑里能扫、手机里不能扫"

`tt.scanCode` 官方文档的支持表里，**PC 那一列是 ✗** —— 飞书 PC 客户端不支持端内扫码。
所以在电脑上打开本应用，扫码走的是「摄像头 / 拍照识别」（本机 jsQR 解码），
跟可信域名无关；只有在**手机飞书**里才会走飞书原生扫码，也就只有那里才需要第 3 步。
两边路径不同，"一边能扫一边不能"通常是可信域名没配，不是应用坏了。

## 三、⚠️ 一个需要你知道的取舍：表格归谁所有

现在这张多维表格是**用应用身份创建的**，所以：

- ✅ 数据确实存在**你们飞书组织**里，不经过我的服务器长期保存（服务端只做转发，不落库）；
- ⚠️ 但它的所有者是「应用」，你在自己的飞书空间里**看不到这张表**，
  也没法直接在飞书里翻台账、看审计记录。

**想要第二种（表格出现在你自己的空间里，随时能打开翻）**，需要这么做：

1. 你在飞书里**自己新建**一个多维表格，命名「FEver 战队物资管理」；
2. 右键/更多 →「**添加文档应用**」→ 选这个自建应用 → 权限选「**可编辑**」；
   （入口：打开多维表格 → 右上角「···」→「···更多」→「添加文档应用」）
3. 把链接发我，我把 6 张表建过去、把已有数据一起迁过去，再重新部署一次。

代价是你要多点几下，换来的是**数据实实在在躺在你自己的空间里**。
如果你觉得没必要——现在这套功能上完全一样，随时可以做迁移，说一声就行。

## 四、现有数据怎么搬过来（重要）

**先说清楚现状**：现在每个队员的浏览器里都有一份自己的数据，互不相通。
共享库现在是**空的**，需要把数据汇总进来：

1. 让**手上有数据的队员**（大概率主要是你一个人）在**旧的地址**上打开系统；
2. 进「**设置与备份**」→ 点「**导出备份**」，会下载一个 `FEver物资备份-日期.json`；
3. 把文件发给你，由你在**新版**（上面那个新地址）里点「**导入恢复**」导入。

> ⚠️ **注意**：「导入恢复」是**整包替换**——它会用备份文件里的内容覆盖整个共享库。
> 所以**只能由一个人、导一次**。如果多个队员分别导入，后导入的会把先导入的冲掉。
> 需要"把几份备份合并起来"的话告诉我，我给你写个合并脚本。

另外建议：**导入之前先把空库备份一次**（点一下「导出备份」即可），万一导错了还能退回来。

## 五、几个要提前知道的限制

| 事项 | 说明 |
| --- | --- |
| **单表最多 2 万条记录** | 飞书多维表格的硬限制。出入库流水增长最快。战队规模下能用很久，但心里有个数；接近上限时我会提醒你分表 |
| **免费版没有行级权限** | "只能改自己登记的东西"这类细粒度控制需要商业版。目前靠**飞书应用可用范围**控制"谁能进"，靠每条记录上的操作人字段满足"谁改过什么"。**审批和兵种预算另有一道"管理员"闸**（`server/config.json` 的 `admins`），但它是应用自己判的、不是飞书的行级权限 |
| **必须联网** | 共享版依赖网络。原来那个本地离线版（`启动物资管理.bat`，端口 8321）**保留不动**，现场没网时可以继续单机登记 |
| **看到别人的更新** | 页面重新获得焦点时会自动同步。想立刻看到最新数据，下拉刷新一下页面最稳 |
| **数据是你们的资产** | 数据存在你们飞书组织自己的多维表格里。服务端只做转发，不落库 |

## 八、飞书消息提醒（审批通知）

**提醒什么时候发**：队员提交采购申请 → 每位管理员收到私聊；管理员批准 → 申请人本人收到私聊。
消息以应用机器人的身份发出，落在「你与 FEver 战队物资管理应用的会话」里。

### 收不到提醒？按这个顺序排查

1. **先在应用里点「发送测试提醒」**（设置与数据备份 → 飞书提醒）。
   它会真发一条消息，并把飞书的**原始返回**显示出来 —— 错误码是什么就是什么，不用猜。
2. **应用功能 → 机器人必须"启用"**。只开 `im:message` 权限是不够的：机器人能力没开，
   私聊消息发不出去或收不到。这是最常见的原因。
3. **开了新权限后要"创建版本并发布"**（开发者后台 → 版本管理与发布）。
   权限只是配置，发布之后才对企业内生效。
4. **可用范围**要包含所有需要收到提醒的人（管理员和申请人）。
5. 管理员名单里写**姓名**的，靠登录记录反查飞书身份 —— 该管理员至少要打开过一次应用。

### 让提醒更醒目：发到群里（可选，推荐）

应用私聊安静；想让整组人第一时间看见，可以用**群自定义机器人**（不需要任何权限）：

1. 打开要接收提醒的飞书群 → 群设置 → 群机器人 → 添加自定义机器人 → 复制 webhook 地址；
2. 把地址填到 `server/config.json` 的 `"groupWebhook"`（可把 `"groupWebhookAtAll"` 设为 `true` 让消息 @所有人）；
3. 重新发布一次（改配置要随应用上传才生效）。

配好之后，每次提交和批准除了私聊，还会**同时发一条到群里**。
