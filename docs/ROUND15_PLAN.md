# 第十五轮：七项功能（已确认方案）

> 需求方 2026-10-06 提出。约束照旧：**不破坏既有功能、手机端与电脑端都要能用、
> 与飞书的关联不能断、每做一项先测再做下一项、最后要完整可用的应用。**
> 下面是逐条问过确认后的定论。「★」标的是我拍的默认值，需求方可以随时推翻。

---

## 1. 物品身份：同款共用 ⇄ 单独使用，后期可改

**结论：两个方向都允许。**

| 方向 | 做法 | 已贴标签的后果 |
| --- | --- | --- |
| 同款共用 → 单独使用 | 原编码保留代表其中 1 件，另发 N−1 个新编码（走 `Rules.nextCodes`，与正常入库同一套编号，不会重号） | **全部继续有效**，不用重贴 |
| 单独使用 → 同款共用 | 保留一个编码（★取编码最小的那个，通常是最早贴的那张），其余编码删除，件数相加 | 被删掉的那些编码对应的标签**作废，需要重贴** → 二次确认里必须写明保留哪个、作废哪几个 |

**前置条件（★）**：待改的这批东西必须**都在库里**（没有借出、没有待修）。
理由：拆分要把新标签一件件贴上，件在外就贴不了；合并会把在外的那些件的编码作废，
人手上的东西就认不出来了。已领用的（`usedUpQty`）在合并方向允许 —— 东西用掉了、标签也没了，不影响。
这条直接复用既有的 `Rules.blockItemDeletion`，不另造一套判断。

**不动库存、不写流水**：改身份不是一次出入库，数量一件不多一件不少（恒等式必须仍然成立）。
合并时删掉的行会记进**删除记录**，保证可追溯。

## 2. 打印标签时可以选择打哪些

标签页加一个**挑选弹窗**（复用「批量下载发票」那个选择器的模式）：
每条一行、带复选框，**★默认全选**（保持"打开就全打"的老习惯）、
「全不选」时下载/打印按钮禁用、实时显示"已选 N / 共 M"。
弹窗内提供**关键字搜索**和**按大类筛**，否则物品一多就翻不动。
原来在物品清单里勾选再点「批量打印标签」的路子**保留不动**。

## 3. 页面互联

| 入口 | 落点 |
| --- | --- |
| 兵种预算某一行（如"共 27 次申请"） | **跳到采购申请页并预置筛选**（兵种 = 该兵种，时间范围 = 当前预算周期），★而不是弹一个只读列表 —— 这样还能接着往下点 |
| 采购申请清单点一下 | **能跳多深跳多深**：已到货 → 直接进物品详情（一批生成了多个身份时，进该大类清单并自动筛出这一批）；还没到货 → 进申请详情（物品还不存在） |
| 发票 / 流水 / 借用台账里出现的物品编码 | 一律可点，跳物品详情（既有行为，顺带统一） |

---

## 4. 全局搜索

**★入口放顶栏**（手机端收成一个图标，避免挤爆导航条）。
范围：**物品 + 大类**——物品按编码 / 名称 / 规格 / 位置 / 兵种 / 所属大类搜；大类按名字搜。
结果按"大类 / 物品"分组：大类点进去是该大类清单，物品点进去是物品详情。
★**不搜单据**（采购申请、发票、流水）——需求方的原话是"搜索单个物品，和大类物品"，
把单据也塞进来只会让结果变杂；真要找单据，第 3 项的互联已经给了入口。

搜索是**全队共享库**上的搜索，不是只搜自己登记的东西。

---

## 5. 打包提交采购申请

**结论：多条申请一起提交，加一个「批次号」——数据结构、审批口径、到货口径、发票口径、兵种预算全部不变。**

- 交互：「新建采购申请」表单上除「提交申请」外，多一个**「先存起来」**；
  攒够之后在**待提交清单**里勾选要提交的，点「打包提交」→ 生成一个批次号，一次提交。
- **管理员只收到一次飞书提醒**（按批次合并，不是每条一条）。
- **待提交清单跟着人走**：存在共享库里、带"谁的"标记，只有自己看得到、也只能提交自己的。
  手机攒一半、回电脑接着攒是通的。离线版没有登录身份，退回"按这台电脑隔离"。
- **审批两种都支持**：批次页给「整批同意」，同时保留逐条同意/驳回。
  驳回默认逐条（每条理由不同）；整批驳回也保留，但要求填一次理由。

---

## 6. 批量确认到货

从批次页勾选"哪些到了"（**允许只到一部分**，没到的还留在批次里）→ 进入**逐条向导**：
按顺序一件一件走「确认到货」表单（实际到货数量、存放位置、发票金额、到货日期、发票 PDF、
身份方式、操作人、备注），走完提交。

**发票粒度：一条申请一张**（结论，不改发票的归属结构）。
为了不重复选文件，向导里给一个**「沿用上一张发票 PDF」**（同一张发票买了多件时点一下就带过来），
金额仍然逐条可改。发票台账、兵种预算里「已到货实际」的口径全部不变。

---

## 7. 按批次打包下载发票 + 提醒

- 批次页上给管理员一个**「打包下载本批发票」**：把这一批里所有申请对应的发票 PDF 打成一个 zip
  （复用既有的 `zip.js` 与发票选择器；缺发票的会明确列出来，不会静默少几张）。
- **发票不全时提醒采购人员**：★**只私聊申请单上填的「申请人」**。
  ⚠️ 飞书私聊只能用 `openId` 发送，而这个 ID 只有在那个人**登录过一次应用**之后才有
  （名单存在设置表里）。**查不到就发不出去** —— 这时界面上要**明说**"XXX 还没登录过应用，
  提醒发不出去"，并给一段可一键复制的催办文本，而不是假装发了。
  群提醒**不开**（需求方 2026-09-22 已明确只要私聊）。

### 顺带修掉的一个既有缺陷
`buildRequestRow`（原 `createRequest` 内联校验）里预算的判据是 `!(n(budget) >= 0)`，
而本文件的 `n()` 会把认不出来的字符串折成 0 —— 于是「乱写」这种预算会被当成 0 元通过校验，
**并且原文照存进预算字段**。现已改成老实判 `isNaN`。
