### ⚠️ 本轮最值钱的一条坑：路由参数在地址栏往返里会丢
`Views.xxx(params)` 的参数要经过 `goto()` → `routeToHash()` → `location.hash` →
`hashchange` → `hashToRoute()` 这一圈。两处必须同时照顾到：
1. **`ROUTES` 表要透传 p**：`purchases: function () { return Views.purchases(); }` 少了 `p`

   以后加筛选条件不用再改），大类用 `#category/<id>/req/<申请号>`。
   解不出来时**兜底成"没带条件"**，不能让手改地址栏把整页打不开。
（labels/scan 早就是这么做的，注释里还写着"刷新后会悄悄退回打印全部物品——那是白费一整叠标签纸的错误"。）

### 第十八轮追加：电脑上「点打印完全没反应」
问过现象后定位：**`window.print()` 在飞书客户端（桌面/手机）里是空操作**，
调用了但打印窗口不弹 —— 这不是代码没跑（端到端里 stub 掉 print 能确认它被调用了）。
**打印样式本身是对的**：`css/style.css` 的 `@media print` 会把 topbar/crumb/no-print/弹窗全隐藏，
只留 `.label-card`（并给标签描边）。所以**在电脑浏览器里按 Ctrl+P 就能打出标签**。
因此做了三件事，让"不依赖 print() "的路子可靠：
1. **PNG 下载改走 Blob URL**（`canvas.toBlob` + `URL.createObjectURL`）：
   标签多时 PNG 几 MB，**Chrome 对超大的 data URL 下载会静默失败**（点了没反应也不报错）——
   那就成了"又点了没反应"，比不给下载更气人。toBlob 不可用时退回 data URL。
2. 标签页常驻说明写清：没反应是因为环境不给打印（飞书客户端就是），
   替代路 = 导出标签图片；或**在电脑浏览器打开同一网址直接 Ctrl+P**。
3. 导出弹窗里给电脑端的具体步骤：下载图片 → 双击打开 → 右键打印 / Ctrl+P。
端到端新增断言：下载必须走 Blob（stub `URL.createObjectURL` 与 `a.click()`，验证 Blob 是 image/png）。

### 第十九轮：真正的病根 = 「筛选只改看得见的行，不改勾选」

   于是"等某个元素出现"会**在旧页面上立刻为真**，后续点击落在**旧闭包**上（拿的是旧数据）。
   解法：**先 `App.goto` 到别的页、确认 data-page 变了，再进目标页**。
2. **`#toast-root` 里留着前面用例的旧提示**，断言"没有提示"会被搅黄 → 先 `innerHTML = ''`。
3. **在 JS 字符串里写正则**：`'\s'` 会被当成未知转义变成 `s`，必须写 `'\\s'`。
   （我先用 Write 写文件、又用 shell 替换，两层转义叠在一起才暴露出来。）



**教训（写进规矩）**：
- 发布目录里**任何"运行时缓存/本地状态"文件都不该存在**；要放也让它是空的、靠远端数据重建。
- **测试禁止写真实文件**。要造假身份就用内存测试口。
- 发布报错**一律以实测为准**。这次见到的两种误报：
  ① `应用预留域名 … 未绑定到本次发布环境…已停止`（编号每次不同）；
  ② `port 3000 NOT listening`（我们的服务听 `process.env.PORT || 8787`，它探的是 3000）。
  两种情况线上其实都活着且已更新 —— 判定方法仍是那四步：逐字节比对、特征串、`/api/data` 401、`uptimeSec`。

## 第二十一轮：出入库流水批量删除

需求：「出入库流水加一个批量删除」。**问了一个问题**（权限）：用户选
「**和单条一样，谁都能删**」—— 不给批量删除另设管理员门槛。

实现与既有「批量删除物品」完全同一套（它的测试在 `cases/batch.js`）：
- `Ops.previewTransactionDeletion(ids)` 只读预演；`Ops.deleteTransactions(ids)`
  **整批一个事务**，删流水与写「删除记录」一起提交（删除记录是读改写，逐条删会互相覆盖、账会丢）。
- 流水没有"能删/不能删"的分流（没有借出/待修那类前置状态），只有"已被别人删了"的竞态，
  按 `missing` 如实报出。
- ⚠️ **不改动物品的库存数量** —— 与单条删除同一口径，页面提示与确认框里都写明了
  （最容易被误解的地方：流水是账本，删流水 ≠ 撤销那次出入库；要改数量得另做一次出入库登记）。
- 界面：流水表多一列勾选框 + 一条批量工具条（全选 / 全不选 / 批量删除（N））。
  全选只作用于**当前筛选出来的**那些；勾选按 id 记，改筛选条件后仍然保留。
- `Rules.txnLabel(row)`：单条删除、批量清单、删除记录**共用同一句人话**（三处一个口径）。

新增测试 `v1/test/cases/txn-delete.js`（7 项）+ M5 端到端一条。

⚠️ 踩到一次**表格加列的连带影响**：在流水表最前面插入勾选框列后，后面所有列右移一格，
而 `desk-tests.js` 那条筛选用例是按**列序号**判断的（`children[1]` 是动作列）→ 失败。
已改成 `children[2]` 并注明原因。**给表格加列前，先搜一遍测试里有没有按列号取值的断言。**
